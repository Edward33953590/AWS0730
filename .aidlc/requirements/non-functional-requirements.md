# 非功能需求文档

## NFR-001 并发安全

- **描述**：库存扣减必须原子操作，不可超发
- **约束**：库存为N时，任意并发请求最多N个成功
- **实现方式**：数据库乐观锁或事务级原子操作
- **验证方式**：并发压测，N+1个请求只有N个返回成功
- **优先级**：P0

---

## NFR-002 幂等性

- **描述**：核销操作必须幂等
- **约束**：同一券码多次核销请求返回一致结果
- **实现方式**：基于券码+状态的幂等处理
- **验证方式**：同一券码连续核销3次，结果一致
- **优先级**：P0

---

## NFR-003 响应时间

- **描述**：普通接口响应在可接受范围内
- **约束**：
  - 普通CRUD接口：< 500ms
  - AI推荐接口：< 10s（含AI调用）
  - AI文案生成：< 15s
  - 风控检测：< 3s（降级规则引擎 < 100ms）
- **验证方式**：接口响应时间测量
- **优先级**：P1

---

## NFR-004 AI降级

- **描述**：AI服务不可用时系统必须正常运行
- **约束**：
  - AI推荐降级 → 热门券列表
  - AI风控降级 → 规则引擎
  - AI文案降级 → 预设模板
  - AI画像降级 → 基础规则标签
- **实现方式**：try-catch + 超时处理 + 降级逻辑
- **验证方式**：模拟AI服务超时/错误，验证降级正常
- **优先级**：P0

---

## NFR-005 安全性

- **描述**：系统基本安全防护
- **约束**：
  - 密码 bcrypt 加密存储（salt rounds >= 10）
  - JWT 认证，令牌有效期7天
  - API 接口权限校验（基于角色）
  - 防止SQL注入（Prisma ORM参数化查询）
  - 输入校验和清洗
  - 敏感操作记录日志
- **验证方式**：尝试越权访问、注入攻击
- **优先级**：P0

---

## NFR-006 数据一致性

- **描述**：系统数据保持一致
- **约束**：
  - 券状态流转严格遵循：未领取→已领取→已核销/已过期/已转赠
  - 库存数 = 总库存 - 已领取数
  - 统计数据与实际记录一致
- **验证方式**：检查数据库一致性
- **优先级**：P0

---

## NFR-007 可用性

- **描述**：系统本地运行稳定
- **约束**：
  - 单机 SQLite 无需外部数据库服务
  - npm run dev 一键启动
  - 支持 Windows/macOS/Linux
- **验证方式**：在目标机器上启动运行
- **优先级**：P0

---

## NFR-008 可维护性

- **描述**：代码结构清晰，易于理解和扩展
- **约束**：
  - TypeScript 严格类型
  - 文件组织按功能模块划分
  - API 接口与前端页面一一对应
  - 关键业务逻辑有注释
- **验证方式**：代码审查
- **优先级**：P1

---

## NFR-009 演示友好性

- **描述**：项目适合竞赛演示
- **约束**：
  - 界面美观实用
  - 操作流程直观，2-3步内完成核心操作
  - 角色切换便捷（退出登录 → 登录其他账号）
  - AI功能有可见输出（推荐理由、文案、风控解释展示在界面上）
  - 加载状态和错误状态有合理展示
- **验证方式**：模拟竞赛演示流程
- **优先级**：P1

---

## NFR-010 环境配置

- **描述**：项目配置简单明确
- **约束**：
  - 所有配置通过 .env.local 文件管理
  - 提供 .env.example 模板
  - 无需复杂环境搭建（无Docker/无外部DB）
  - 数据库自动初始化（Prisma migrate）
- **验证方式**：新环境克隆后按文档启动
- **优先级**：P0
