## ADR-M-001: 使用 html5-qrcode 而非原生扫码

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 扫码功能需要读取摄像头，选择什么方案？
- **选项**:
  - A) 原生 `getUserMedia` API + 自己处理解码
  - B) `html5-qrcode` CDN 库（基于 `getUserMedia` 封装）
  - C) 后端扫码（上传图片 → 后端解码）
- **决策**: B) html5-qrcode CDN 库
- **理由**:
  - 前端 CDN 方案最简单，零依赖安装
  - 库封装了相机权限请求和解码逻辑
  - 与本项目现有的 TailwindCSS CDN + Alpine.js CDN 模式一致
  - 扫码实际上由手机相机系统完成（扫描 URL），前端只是落地页
- **影响**: 前端只需要调用一次 `POST /api/redeem`，不需要额外的扫码页面

## ADR-M-002: 扫码落地页使用 `/v/` 短路径

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 二维码中的 URL 应该用什么路径？
- **选项**:
  - A) `/v/CPN-XXXX` (短路径)
  - B) `/verifier/scan/CPN-XXXX` (完整路径)
  - C) `/scan/CPN-XXXX` (中等长度)
- **决策**: A) `/v/CPN-XXXX`
- **理由**:
  - 二维码越短越密集，扫码识别率越高
  - 评委看到 URL 更简洁美观
  - 路由不需要中间件权限保护，因为页面自己会判断登录状态
- **影响**: 需要在 `verifier.py` 中注册一个短路径路由

## ADR-M-003: 使用内嵌登录而非跳转到登录页

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 扫码后发现未登录，怎么处理？
- **选项**:
  - A) 跳转到登录页，登录后跳回扫码页
  - B) 页面内嵌登录表单，登录后自动核销
  - C) 弹窗登录
- **决策**: B) 内嵌登录表单
- **理由**:
  - 跳转会导致扫码上下文丢失（用户可能不知道核销哪个券码）
  - 内嵌登录让流程更流畅：扫码 → 看见券码 → 登录 → 自动核销
  - 演示时效果更好，一个页面完成全部操作
- **影响**: scan_login.html 需要包含登录表单 + 核销逻辑

## ADR-M-004: PWA 而非原生 App

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 移动端以什么形式提供给用户？
- **选项**:
  - A) PWA (manifest + Service Worker)
  - B) 原生 App（Flutter / React Native）
  - C) 纯浏览器访问，不做任何包装
- **决策**: A) PWA
- **理由**:
  - 0 额外开发工时（只需要 manifest.json + sw.js）
  - 可添加到主屏幕，沉浸式体验（无浏览器地址栏）
  - 扫码落地页在 PWA 中打开后体验接近原生
- **影响**: 需要 HTTPS 才能安装 PWA（localhost 允许）

## ADR-M-005: app.py 绑定 `host='0.0.0.0'`

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 手机和电脑在同一个 WiFi，手机怎么访问网页？
- **选项**:
  - A) `host='0.0.0.0'` 绑定所有网卡
  - B) nginx 反向代理
  - C) ngrok 内网穿透
- **决策**: A) `host='0.0.0.0'`
- **理由**:
  - 最简单，不需要额外工具
  - 手机和电脑在同一 WiFi 下可直接用 IP 访问
  - 二维码中使用 `window.location.origin` 自动适配
  - ngrok 需要外网且演示环境可能不稳定
  - nginx 增加部署复杂度
- **影响**: `app.run(host='0.0.0.0', debug=True, port=5000)`
- **风险**: WiFi 下其他设备也能访问，但演示环境无安全风险

## ADR-M-006: 使用 Web Share API 实现分享功能

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: 用户如何分享优惠券？
- **选项**:
  - A) Web Share API (`navigator.share()`)
  - B) 生成分享链接 + 二维码
  - C) 复制到剪贴板
- **决策**: A) Web Share API + 降级 B
- **理由**:
  - Web Share API 在手机上调用系统分享菜单，体验最佳
  - 桌面端不支持时降级为复制链接
  - 与本项目的 CDN 模式一致，零依赖
- **影响**: M-007 中实现

## ADR-M-007: 独立 Blueprint 实现 `/v/` 短路径路由

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: `/v/<coupon_code>` 应该放在哪个蓝图？
- **选项**:
  - A) 放在 `verifier_bp`（已注册 `/verifier` 前缀）
  - B) 创建新的 `scan_bp`（无前缀）
  - C) 直接用 `@app.route` 在 app.py 中定义
- **决策**: B) 新建 `routes/scan.py` + `scan_bp` 蓝图（无前缀）
- **理由**:
  - A 选项会导致 URL 变成 `/verifier/v/`，不符合短路径需求
  - C 选项会导致路由分散在 app.py 中，不利于维护
  - scan_bp 职责单一：只处理 `/v/<code>` 扫码落地页
- **影响**: 需要在 `app.py` 中注册 `scan_bp`（无 `url_prefix`）

## ADR-M-008: 核销记录页面使用 `records.html` 而非 `index.html`

- **日期**: 2026-07-30
- **状态**: ✅ 已确认
- **问题**: `/verifier/records` 路由渲染哪个模板？
- **背景**: 之前 `verifier.py` 中 `@verifier_bp.route('/records')` 错误地渲染了 `verifier/index.html`
- **决策**: 改为渲染 `verifier/records.html`（新创建的文件）
- **理由**:
  - 语义正确：记录页面应该渲染记录模板
  - index.html 是核销首页，两者功能不同
- **影响**: 创建 records.html，修改路由返回值
