# 功能需求文档

## FR-001 用户注册

- **描述**：用户可通过注册页面创建账户
- **角色**：公开（未登录）
- **前置条件**：无
- **业务规则**：
  - 用户名唯一，不可重复
  - 密码使用 bcrypt 加密存储
  - 注册时必须选择角色（管理员/运营人员/核销人员/普通用户）
  - 用户名长度 3-20 字符，密码长度 6-50 字符
- **正常结果**：注册成功，返回用户信息和JWT令牌，自动登录
- **异常处理**：
  - 用户名已存在 → 提示"用户名已被占用"
  - 参数校验失败 → 返回具体字段错误信息
- **优先级**：P0
- **来源**：setup.md 第三节
- **验收标准**：注册成功后可立即登录，角色权限生效

## FR-002 用户登录

- **描述**：已注册用户通过用户名+密码登录系统
- **角色**：公开
- **前置条件**：用户已注册
- **业务规则**：
  - 验证用户名和密码
  - 登录成功签发 JWT 令牌（有效期7天）
  - 登录后根据角色跳转到对应的功能页面
- **正常结果**：返回JWT令牌和用户信息（含角色）
- **异常处理**：
  - 用户名不存在 → 提示"用户名或密码错误"
  - 密码错误 → 提示"用户名或密码错误"（不暴露具体哪个错）
- **优先级**：P0
- **来源**：setup.md 第三节
- **验收标准**：登录后能访问对应角色页面，无法访问其他角色页面

## FR-003 活动创建

- **描述**：运营人员创建优惠券活动，配置各项参数
- **角色**：运营人员
- **前置条件**：用户已登录且角色为运营人员
- **业务规则**：
  - 必填字段：活动名称、优惠券类型、库存数量
  - 选择类型后自动填充默认参数值
  - 支持7种类型：满减、折扣、无门槛、加购、品类、新人、限时
  - 有效期模式：领取后N天（默认1天）或 固定日期范围
  - 默认值：库存100张、有效期1天、每人限领1张
  - 可设置：是否可转赠（默认关）、是否可叠加（默认关）、分享领取次数（默认3）
  - 可设置活动开始时间（定时开放领取）
- **正常结果**：活动创建成功，状态为"待开始"或"进行中"
- **异常处理**：
  - 必填字段缺失 → 表单校验提示
  - 库存为0或负数 → 拒绝创建
  - 结束时间早于开始时间 → 拒绝创建
- **优先级**：P0
- **来源**：setup.md 第四/五节
- **验收标准**：创建后在活动列表可见，参数配置正确

## FR-005 用户领取优惠券

- **描述**：普通用户从活动中领取优惠券
- **角色**：普通用户
- **前置条件**：活动进行中、有库存、用户未超过限领数
- **业务规则**：
  - 库存原子扣减（并发安全，不可超发）
  - 每用户限领校验
  - 新人券仅注册后首次领取的用户可领
  - 限时券需在指定时间段内
  - 领取时生成唯一券码（格式：CPN-XXXXXXXX，8位大写字母+数字）
  - 领取时触发风控检测
  - 有效期根据活动设置计算（领取后N天 或 固定截止日期）
- **正常结果**：领取成功，优惠券出现在用户券包，库存减1
- **异常处理**：
  - 库存不足 → 返回"库存不足"
  - 已达限领数 → 返回"已领取"
  - 活动未开始 → 返回"活动未开始"
  - 活动已结束 → 返回"活动已结束"
  - 风控拦截 → 返回"操作异常，已被拦截"
  - 黑名单用户 → 返回"无法领取"
- **优先级**：P0
- **来源**：setup.md 5.2、需求文档 AC-1/AC-2
- **验收标准**：库存N，N+1并发请求只有N个成功；同一用户重复领取返回"已领取"

## FR-006 优惠券核销

- **描述**：核销人员通过输入券码完成优惠券核销
- **角色**：核销人员
- **前置条件**：用户已登录且角色为核销人员
- **业务规则**：
  - 核销人员输入券码 → 点击核销按钮
  - 幂等核销：重复核销同一券码返回一致结果
  - 过期券不可核销
  - 已核销券再次核销返回"已核销"状态
  - 核销成功记录核销时间和核销人员
- **正常结果**：核销成功，券状态变为"已核销"
- **异常处理**：
  - 券码不存在 → 返回"无效券码"
  - 券已过期 → 返回"券已过期"
  - 券已核销 → 返回"已核销"（幂等，含首次核销信息）
  - 券未被领取 → 返回"券未激活"
- **优先级**：P0
- **来源**：setup.md 5.3、需求文档 AC-3/AC-4
- **验收标准**：过期券核销返回"券已过期"；重复核销幂等

## FR-007 AI智能推券

- **描述**：根据用户历史行为，AI生成个性化优惠券推荐列表和推荐理由
- **角色**：普通用户
- **前置条件**：用户已登录
- **业务规则**：
  - 触发时机：用户进入领券页面自动加载 + 可点"刷新推荐"按钮
  - 输入：用户领券记录、核销记录、浏览行为
  - 输出：推荐优惠券列表（至少1条）+ 每条推荐的理由文本
  - AI不可用时降级：返回热门券列表（按领取量排序）
- **正常结果**：返回非空推荐列表，每项含优惠券信息+推荐理由
- **异常处理**：
  - AI超时 → 降级返回热门券列表
  - AI返回空结果 → 降级返回热门券列表
- **优先级**：P0
- **来源**：setup.md 6.1、需求文档 AC-5
- **验收标准**：返回非空推荐列表+理由文本；AI不可用时降级正常

## FR-008 AI异常检测（风控）

- **描述**：领券时评估用户行为风险，返回评分与决策
- **角色**：系统内部（领券时自动触发）
- **前置条件**：用户发起领券请求
- **业务规则**：
  - 输入：用户ID、请求频率、历史行为、IP等
  - 输出：风险评分(0-100)、决策（放行/拦截/人工审核）、原因
  - AI模式：调用Bedrock分析行为模式
  - 降级模式（规则引擎）：
    - R-1：10秒内50次请求 → 拦截
    - R-2：1分钟内领10张不同券 → 人工审核
    - R-3：注册不足5分钟批量领券 → 人工审核
    - R-4：同IP短时间多账号领券 → 拦截
    - R-5：黑名单用户 → 拦截
    - R-6：白名单用户 → 放行
  - AI异常行为解释：用自然语言解释判定原因
- **正常结果**：返回风险评分、决策和解释
- **异常处理**：
  - AI不可用 → 自动降级为规则引擎
  - 规则引擎也异常 → 默认放行（记录日志）
- **优先级**：P0
- **来源**：setup.md 6.2/11、需求文档 AC-6
- **验收标准**：10秒50次领取触发拦截；AI不可用时规则引擎接管

## FR-014 优惠券转赠

- **描述**：用户将已领取的优惠券转赠给其他用户
- **角色**：普通用户
- **前置条件**：优惠券活动设置允许转赠、券状态为"待使用"、券未过期
- **业务规则**：
  - 输入目标用户的用户名
  - 转赠后原用户券消失，目标用户获得该券
  - 不可转赠给自己
  - 目标用户必须存在
  - 转赠后有效期不重置
- **正常结果**：转赠成功，双方收到通知
- **异常处理**：
  - 活动不允许转赠 → 提示"该券不可转赠"
  - 目标用户不存在 → 提示"用户不存在"
  - 券已过期/已核销 → 提示"该券无法转赠"
- **优先级**：P2
- **来源**：setup.md 5.2
- **验收标准**：转赠后原用户券包减少，目标用户券包增加

- **正常结果**：返回用户画像标签列表和描述
- **异常处理**：AI不可用 → 基于规则生成基础标签（如领券频率分级）
- **优先级**：P2
- **来源**：setup.md 6.4
- **验收标准**：画像标签与用户实际行为相关

## FR-024 叠加使用规则

- **描述**：运营设置优惠券是否可与其他券叠加使用
- **角色**：运营人员（设置）、核销人员（核销时校验）
- **前置条件**：活动创建/编辑时
- **业务规则**：
  - 运营创建活动时选择"可叠加"或"不可叠加"
  - 核销时如果券设为不可叠加，同一用户同一次消费只能核销一张
  - 可叠加的券无此限制
- **正常结果**：叠加规则正确执行
- **异常处理**：不可叠加券重复核销 → 提示"该券不可叠加使用"
- **优先级**：P2
- **来源**：setup.md 5.1
- **验收标准**：不可叠加券在同一消费场景只能使用一张
